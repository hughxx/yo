CoreInsight LocalToolkit 前端接口（统一信封版）
Base URL: http://127.0.0.1:17831

统一响应：
所有成功接口的 HTTP status 均为 200。
成功响应：code=200，msg=ok，data=实际业务数据；前端统一从 data 取值。
错误响应：HTTP status 保留 409/422/426/502/500 等，code 与 HTTP status 相同，msg 为错误原因，data=null。
以下各接口所述“响应”均指信封中的 data 字段。

一、页面初始化

1. GET /health
时机：页面打开时首先调用，判断 LocalToolkit 是否启动。

2. GET /welink/cli/status
时机：/health 成功后调用，判断 welink-cli 是否安装且可用。
使用：ready=true 才允许预览消息和启动提取。

3. GET /welink/skill/list
时机：页面初始化时调用，填充 Skill 选择列表。

4. GET /welink/group/list
时机：页面初始化、添加/修改/删除群组、任务状态结束后调用，刷新群组配置和状态。
定时相关返回字段：
{
  "scheduleEnabled": true,
  "scheduleSince": "2026-08-17 10:00:00",
  "scheduleCursor": "2026-08-18 09:00:00",
  "scheduleLastRun": "2026-08-18 09:00:00",
  "scheduleNextRun": "2026-08-19 09:00:00"
}
使用：scheduleSince 是用户设置的首次起点；scheduleCursor 是系统当前成功游标；scheduleLastRun 是兼容字段，正式前端读取 scheduleCursor。
使用：定时任务结束后重新调用本接口，刷新 scheduleCursor 和 scheduleNextRun。

5. GET /welink/extract/tasks
时机：页面初始化时调用，恢复各群组未结束任务及近期任务状态。


二、群组管理

6. POST /welink/group/add
时机：用户添加群组时调用。
请求：
{
  "groupId": "群组ID",
  "name": "群组名称"
}

7. PUT /welink/group/update
时机：用户保存群组配置时调用。
使用：提交 GET /welink/group/list 返回的完整群组对象，修改其中的用户配置字段后整体提交。
使用：startTime、endTime、quickRange 只用于“指定时间范围”的手动提取。
使用：不要通过本接口修改 scheduleSince、scheduleCursor、scheduleLastRun、scheduleNextRun；定时配置统一调用 /welink/schedule/set。

8. DELETE /welink/group/delete
时机：用户删除群组时调用。
请求：
{
  "groupId": "群组ID"
}
使用：群组存在未结束任务时会返回 409，应先取消任务。


三、消息预览

9. POST /welink/message/page
时机：用户打开消息预览、刷新预览、点击“加载更早消息”时调用。
首次请求：
{
  "groupId": "群组ID",
  "startTime": "2026-08-10 00:00:00",
  "endTime": "2026-08-17 23:59:59",
  "cursor": "",
  "limit": 100
}
加载更早消息：把上一次响应的 nextCursor 传入 cursor。
停止条件：hasMore=false。
响应：
{
  "items": [],
  "nextCursor": "",
  "hasMore": false,
  "totalHint": 0
}
注意：totalHint 不能用来判断历史消息总数。


四、手动提取

10. POST /welink/extract
时机：用户点击“提取”时调用。
请求：
{
  "groupId": "群组ID",
  "startTime": "2026-08-10 00:00:00",
  "endTime": "2026-08-17 23:59:59",
  "skillId": "welink-experience-extractor",
  "extractMode": "direct",
  "uploadBy": "当前登录用户账号",
  "selection": {
    "mode": "all",
    "excludedMessageIds": [],
    "selectedMessageIds": []
  }
}
使用：保存响应中的 data.taskId，并立即开始查询该任务状态。
规则：同群组已有未结束任务时返回 409；其他群组的任务会正常进入 queued 队列。
规则：该群组已启用定时提取时，应先调用 /welink/schedule/cancel。

selection 用法：
全部提取：mode=all，用户取消勾选的 ID 放入 excludedMessageIds。
明确选择：mode=explicit，选中的 ID 放入 selectedMessageIds。
不传聊天正文，只传消息 ID 选择条件。

11. GET /welink/extract/status?taskId={taskId}
时机：POST /welink/extract 成功后轮询；建议每 2 秒调用一次。
停止条件：running=false。
结果判断：status=done 成功；status=failed 读取 error；status=cancelled 已取消；status=queued 正在排队。

12. GET /welink/extract/status?groupId={groupId}
时机：需要恢复或刷新某一个群组的最近任务状态时调用。

13. POST /welink/extract/cancel
时机：用户取消某个提取任务时调用。
推荐请求：
{
  "taskId": "任务ID"
}
没有 taskId 时也可以按群组：
{
  "groupId": "群组ID"
}


五、定时提取

页面：将“指定时间范围”和“定时增量”作为互斥选项。
指定时间范围：显示 startTime、endTime、消息预览和手动提取。
定时增量：显示 since、执行频率和执行时间；不显示消息勾选。

14. POST /welink/schedule/set
时机：用户确认新增或修改定时提取配置时调用。
请求：
{
  "groupId": "群组ID",
  "uploadBy": "当前登录用户账号",
  "skillId": "welink-experience-extractor",
  "extractMode": "direct",
  "scheduleFreq": "daily",
  "scheduleTime": "09:00:00",
  "scheduleCron": "",
  "since": "2026-08-17 10:00:00"
}
使用：scheduleFreq 支持 daily、weekly、monthly、custom；custom 时填写五段 Cron。
使用：首次设置定时必须传 since，表示首次增量起点；运行窗口为 (since, 本次触发时间]。
使用：修改频率但不重置进度时省略 since；重新传 since 会重置增量游标，可能重复提取。
使用：定时模式固定处理增量窗口内全部消息，不使用手动预览的 selection。
使用：同群组存在未结束任务时返回 409。
响应：返回完整群组对象；保存其中的 scheduleSince、scheduleCursor、scheduleNextRun。

15. POST /welink/schedule/cancel
时机：用户点击“取消定时”，或手动提取前需要取消该群组定时时调用。
请求：
{
  "groupId": "群组ID"
}
使用：取消后保留 scheduleSince 和 scheduleCursor，不删除历史增量进度。
使用：取消后重新启用时必须传希望使用的 since；要接着上次进度，传当前 scheduleCursor。


六、统一处理

本次定时改动没有新增或删除接口。
请求变更：POST /welink/schedule/set 新增 since。
响应变更：群组对象新增 scheduleSince、scheduleCursor；scheduleLastRun 仅兼容保留。
未变化：消息预览、手动提取、任务轮询和取消接口路径均不变。

时间格式：YYYY-MM-DD HH:mm:ss。
POST /welink/extract 返回成功只表示任务已受理，不代表提取已完成。
403：当前网页 Origin 不在 LocalToolkit 白名单。
404：群组或任务不存在，或群组尚未绑定。
409：同群组任务或定时状态冲突。
422：请求字段或时间格式错误。
426：LocalToolkit 必须升级，停止继续调用 WeLink 业务接口。
502：welink-cli、Hermes、文件服务或下游调用失败。


七、邮件提取

16. GET /email/status
时机：邮件页面初始化时调用，检测本机 Outlook。
使用：ready=true 才允许读取文件夹、邮件和启动提取。

17. GET /email/skill/list
时机：邮件页面初始化时调用，填充邮件 Skill 列表。

18. GET /email/folder/list
时机：首次进入邮件页面或用户刷新文件夹时调用。
响应项：path、name、depth。前端保存和提交 path。

19. GET /email/config
时机：邮件页面初始化、定时任务结束后调用。
响应：folders、rules、blacklist、skillId、extractMode、uploadBy，以及 scheduleEnabled、scheduleSince、scheduleCursor、scheduleNextRun。

20. PUT /email/config
时机：文件夹、规则、黑名单、Skill、入库方式或用户工号变化后调用。
请求：提交 GET /email/config 的完整对象。
规则字段：id、name、subjectKeywords、bodyKeywords、senders、logic(OR/AND)、enabled。
使用：不要通过本接口修改 schedule 字段。

21. POST /email/message/list
时机：刷新邮件、搜索、切换规则筛选或翻页时调用。
请求：
{
  "folders": ["邮箱 - 用户\\收件箱"],
  "startTime": "2026-08-10 00:00:00",
  "endTime": "2026-08-17 23:59:59",
  "query": "GaussDB",
  "matchedOnly": false,
  "offset": 0,
  "limit": 100
}
响应：items、total、offset、limit、hasMore。
items 中 matchedRule 表示命中的提取规则；blockedRule 表示被黑名单排除。

22. POST /email/message/get
时机：用户点击邮件预览时调用。
请求：{"itemId":"Outlook EntryID"}
使用：只读取正文预览，不上传附件、不执行 OCR。

23. POST /email/extract
时机：用户确认提取选中邮件时调用。
请求：
{
  "folders": ["邮箱 - 用户\\收件箱"],
  "startTime": "2026-08-10 00:00:00",
  "endTime": "2026-08-17 23:59:59",
  "query": "",
  "matchedOnly": false,
  "skillId": "email-experience-extractor",
  "extractMode": "direct",
  "uploadBy": "当前登录用户账号",
  "selection": {
    "mode": "explicit",
    "selectedItemIds": ["Outlook EntryID"],
    "excludedItemIds": []
  }
}
使用：前端只传 EntryID，不传邮件正文和附件。LocalToolkit 重新从 Outlook 读取，生成 Markdown、图片 OCR 和公开链接，再运行 Skill。
全部条件结果可用 mode=all，并将取消勾选项放入 excludedItemIds。

24. GET /email/extract/status
时机：POST /email/extract 成功后每 2 秒轮询。
停止条件：running=false。status 含 fetching、workspace、skill、pushing、done、failed、cancelled。

25. GET /email/extract/tasks
时机：页面初始化时恢复最近邮件任务状态。

26. POST /email/extract/cancel
时机：用户取消正在运行的邮件任务时调用。请求体可为空对象。

27. POST /email/schedule/set
时机：新增或修改邮件定时增量提取时调用。
请求：
{
  "folders": ["邮箱 - 用户\\收件箱"],
  "uploadBy": "当前登录用户账号",
  "skillId": "email-experience-extractor",
  "extractMode": "direct",
  "scheduleFreq": "daily",
  "scheduleTime": "09:00:00",
  "scheduleCron": "",
  "since": "2026-08-17 10:00:00"
}
使用：首次设置或重置游标时传 since；只修改频率时省略 since。
运行窗口为 (scheduleCursor, 本次触发时间]。成功才推进 scheduleCursor，失败或取消不推进。
定时任务只处理提取规则命中且未被黑名单排除的邮件。必须至少配置并启用一条包含主题、正文或发件人条件的有效提取规则；否则接口返回 422，不会创建全量增量任务。

28. POST /email/schedule/cancel
时机：用户取消邮件定时提取时调用。请求体可为空对象。
使用：取消后保留 scheduleSince 和 scheduleCursor。

邮件时间格式同样统一为 YYYY-MM-DD HH:mm:ss。
503：Outlook 未安装、未登录或访问组件不可用。
