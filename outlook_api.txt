CoreInsight LocalToolkit - Outlook 邮件提取前端接口

基础地址：http://127.0.0.1:17831

统一响应格式

成功：
{
  "code": 200,
  "msg": "ok",
  "data": 实际业务数据
}

失败：
{
  "code": 422,
  "msg": "错误原因",
  "data": null
}

说明：
- 所有成功响应的 HTTP 状态码和 code 均为 200，包括启动异步任务。
- 失败时 HTTP 状态码与 code 相同。
- 前端业务数据统一读取 response.data.data。
- 时间统一传 YYYY-MM-DD HH:mm:ss；没有起止限制时传 null。


一、页面初始化

1. GET /health

时机：进入邮件页面时，先检测 LocalToolkit 是否已经启动。

data：

  "service": "coreinsight-local-toolkit",
  "version": "0.5.0"
}

  "emailRuleFiltering": true,

二、文件夹、规则和配置

5. GET /email/folder/list

时机：首次邮件列表加载完成后调用，或用户点击“刷新文件夹”时调用。

data：
[
  {
    "path": "waxxx@xxs.xxx.com\\收件箱",
    "name": "收件箱",
    "depth": 1,
    "isDefault": true
  }
]

使用：
- path 是当前用户 Outlook 账户的真实路径，不能写死；例如 `waxxx@xxs.xxx.com\\收件箱`。前端显示 name 和层级，保存及后续请求提交 path。
- LocalToolkit 内部通过 Outlook `GetDefaultFolder(INBOX)` 获取默认收件箱的 `EntryID`，再与文件夹树节点的 `EntryID` 匹配生成 `isDefault=true`；这个 ID 不需要返回给前端。
- isDefault=true 的文件夹就是当前账户默认收件箱，前端只自动勾选这一项。
- 用户取消所有勾选时 folders=[]，邮件列表应为空，不得回退扫描默认收件箱。
- 调用期间左侧文件夹区域显示独立转圈和“正在读取文件夹…”，不得遮挡或阻塞整个邮件主页。
- 首次进入时由扫描任务负责读取 Outlook；扫描完成后再显示缓存列表。本接口可与扫描任务并行调用。
- 读取失败时保留主页，文件夹区域显示“读取失败，可点击刷新重试”，并展示接口 msg。


6. PUT /email/config

时机：保存扫描文件夹、提取规则、黑名单，或保存 Skill、入库方式、用户工号时调用。

请求：
{
  "folders": ["邮箱 - 用户\\收件箱"],
  "rules": [
    {
      "id": "已有规则传原 ID；新增规则可传空字符串",
      "name": "故障经验",
      "subjectKeywords": ["故障", "异常"],
      "bodyKeywords": ["根因", "解决方案"],
      "senders": ["zhangsan", "@huawei.com"],
      "logic": "OR",
      "enabled": true
    }
  ],
  "blacklist": [],
  "skillId": "email-experience-extractor",
  "extractMode": "direct",
  "uploadBy": "w00899061"
}

字段：
- logic：OR 或 AND。
- extractMode=direct：提取结果由 LocalToolkit 直接写入经验中心。
- extractMode=draft：提取结果由 LocalToolkit 内部调用草稿新建/更新接口，写入平台待确认经验。
- 无论 direct 还是 draft，前端都只调用 LocalToolkit 的 /email/extract，不直接调用远端经验或草稿接口。
- 新增规则保存后，响应会返回 LocalToolkit 生成的规则 ID。
- 有效提取规则必须 enabled=true，并至少填写 subjectKeywords、bodyKeywords、senders 中的一类。
- 删除或禁用最后一条有效提取规则时，已有邮件定时任务会被停止，但保留增量游标。
- schedule 字段由定时接口管理，不通过本接口修改。

响应 data：完整 EmailConfig。


无有效规则红色提醒条

显示条件：当前不存在任何有效提取规则。有效规则必须同时满足：
- enabled=true；
- subjectKeywords、bodyKeywords、senders 至少有一项非空。

前端表现：
- 提醒条固定放在“时间范围”下方、邮件表格上方，使用浅红背景和红色边框，不要只用 toast。
- 文案：“尚未配置有效的提取规则。全量读取可能涉及隐私信息，请先配置提取规则。”
- 右侧显示“去配置规则”按钮，点击后直接打开提取规则编辑区域。
- 无有效规则时禁用“仅显示规则命中”复选框，并取消其勾选状态。
- 保存至少一条有效规则后立即隐藏提醒条；删除或禁用最后一条有效规则后立即重新显示。
- 该提醒判断的是“有没有配置有效规则”，不是当前邮件列表有没有匹配结果。
- 手动明确勾选邮件仍可提取；定时增量必须有有效规则，否则不得打开定时配置并提示用户先配置规则。


三、邮件列表与预览

7. POST /email/message/scan

时机：邮件页面首次进入、用户点击“刷新邮件”时调用。接口只启动后台扫描，不等待 Outlook 全量读取完成。

请求：
{
  "folders": ["邮箱 - 用户\\收件箱"],
  "forceFull": false
}

说明：
- folders 为空时扫描 Outlook 默认收件箱。
- 首次扫描或 forceFull=true：全量读取所选文件夹摘要，不按 50/500/10000 条截断。
- 已有本地缓存且文件夹范围未变化时：只读取缓存最新邮件之后的增量，再与缓存合并。
- 同一时间只能运行一个扫描任务；正在扫描时返回 HTTP 409。

成功 data：
{
  "running": true,
  "taskId": "scan-task-id",
  "status": "scanning",
  "scanned": 0,
  "total": 0,
  "incremental": false,
  "message": "正在全量读取邮件"
}


8. GET /email/message/scan/status

时机：调用 scan 后每 1 秒轮询，直到 status 为 done 或 failed。

扫描中 data：
{
  "running": true,
  "taskId": "scan-task-id",
  "status": "scanning",
  "scanned": 1250,
  "total": 0,
  "incremental": false,
  "message": "正在全量读取邮件：已读取 1250 封"
}

完成 data：
{
  "running": false,
  "taskId": "scan-task-id",
  "status": "done",
  "scanned": 8632,
  "total": 8632,
  "incremental": false,
  "message": "全量读取完成",
  "items": [
    {
      "id": "Outlook EntryID",
      "subject": "邮件主题",
      "senderName": "张三",
      "senderEmail": "zhangsan@huawei.com",
      "receivedTime": "2026-08-18 15:30:00",
      "timestamp": 1787038200000,
      "conversationTopic": "会话主题",
      "folder": "邮箱 - 用户\\收件箱",
      "hasAttachments": true
    }
  ]
}

失败时 status=failed，error 提供错误原因。前端应保留页面并提供重新扫描按钮。


9. POST /email/message/list

用途：扫描完成后对本地缓存做分页、搜索和规则过滤；不会因翻页再次读取 Outlook。

请求：
{
  "folders": ["邮箱 - 用户\\收件箱"],
  "startTime": null,
  "endTime": null,
  "query": "GaussDB",
  "matchedOnly": false,
  "offset": 0,
  "limit": 50
}

data：沿用原 items/total/offset/limit/hasMore/scanned 字段；缓存扫描完成后 totalExact 固定为 true，可显示“共 N 封 / 当前页 / 总页数”。

字段：
- 全量邮件列表默认 startTime、endTime 均传 null；不再默认限制今天、最近 7 天或最近 30 天。
- matchedOnly=true：只返回命中提取规则且未被黑名单排除的邮件。
- limit 范围为 1 至 500。
- 查询、翻页、切换规则过滤只操作本地缓存，仍需显示表格区域加载状态。
- 不要在扫描未完成时调用本接口。
- 同一次扫描快照内，未点击“刷新邮件”或未改变文件夹时，total 不得重新计算或变化。
- 翻页必须先将 page 重置为 0；只有 hasMore=true 才允许进入下一页，避免出现“第 2 / 1 页”。


10. POST /email/message/get

时机：用户点击某封邮件的“预览”时调用。

请求：
{
  "itemId": "Outlook EntryID"
}

data 主要字段：
{
  "id": "Outlook EntryID",
  "subject": "邮件主题",
  "senderName": "张三",
  "senderEmail": "zhangsan@huawei.com",
  "receivedTime": "2026-08-18 15:30:00",
  "htmlBody": "<html>...</html>",
  "body": "纯文本正文",
  "hasAttachments": true
}

使用：本接口只用于正文预览，不上传附件、不执行 OCR。正式提取时由 LocalToolkit 重新读取正文和附件。


四、手动提取

11. POST /email/extract

时机：用户在“提取选中”弹窗确认 Skill、入库方式和用户工号后调用。

请求：
{
  "folders": ["邮箱 - 用户\\收件箱"],
  "startTime": "2026-08-11 00:00:00",
  "endTime": "2026-08-18 23:59:59",
  "query": "",
  "matchedOnly": false,
  "skillId": "email-experience-extractor",
  "extractMode": "direct",
  "uploadBy": "w00899061",
  "selection": {
    "mode": "explicit",
    "selectedItemIds": ["Outlook EntryID-1", "Outlook EntryID-2"],
    "excludedItemIds": []
  }
}

使用：
- 前端只传 Outlook EntryID，不传邮件正文或附件。
- 当前前端固定使用 selection.mode=explicit，避免无意全量提取。
- folders、时间、query、matchedOnly 应与生成当前选择集合时的筛选条件一致。
- LocalToolkit 会重新读取邮件，将 HTML 转成 Markdown，处理附件、图片公开链接和 OCR，再运行 Skill。
- extractMode=direct 时由 LocalToolkit 写入正式经验；extractMode=draft 时由 LocalToolkit 创建或更新待确认草稿，前端无需调用其他写入接口。

data：
{
  "running": true,
  "taskId": "任务 ID",
  "status": "fetching",
  "scanned": 0,
  "selected": 0,
  "processed": 0,
  "message": "正在读取 Outlook 邮件",
  "error": "",
  "docId": "",
  "docIds": [],
  "title": "",
  "scheduled": false
}


12. GET /email/extract/status

时机：页面初始化时调用一次；POST /email/extract 成功后每 2 秒轮询。

停止轮询：running=false。

status：
- idle：空闲。
- fetching：读取 Outlook 邮件。
- workspace：转换邮件、附件、图片和 Markdown。
- skill：Skill 执行中。
- pushing：写入经验或草稿。
- done：成功。
- failed：失败，读取 error。
- cancelled：已取消。

成功后的 data 还会包含 docId、docIds、title；scheduled 表示是否由定时任务触发。


13. POST /email/extract/cancel

时机：用户点击“停止提取”时调用。

请求体：{}，也可以不发送请求体。

data：取消请求提交后的当前任务状态。取消是协作式的，前端继续轮询，直到 running=false 且 status=cancelled。


五、定时增量

14. POST /email/schedule/set

时机：用户在“启动定时”或“修改定时”弹窗保存时调用。

请求：
{
  "folders": ["邮箱 - 用户\\收件箱"],
  "uploadBy": "w00899061",
  "skillId": "email-experience-extractor",
  "extractMode": "direct",
  "scheduleFreq": "daily",
  "scheduleTime": "09:00:00",
  "scheduleCron": "",
  "since": "2026-08-18 00:00:00"
}

字段：
- scheduleFreq：daily、weekly、monthly、custom。
- scheduleFreq=custom 时填写 scheduleCron，格式为“分 时 日 月 星期”。
- 首次创建或主动重置增量起点时传 since。
- 仅修改执行频率、执行时间、Skill 或入库方式时省略 since，保留现有 scheduleCursor。
- 用户选择“从最早记录开始”时，since 传 1970-01-01 00:00:00。
- 必须先通过 PUT /email/config 保存至少一条有效且启用的提取规则，否则返回 422。
- 定时任务只处理提取规则命中且未被黑名单排除的邮件，不允许无规则全量增量扫描。
- 每次窗口为 (scheduleCursor, 本次触发时间]；全部处理成功才推进 scheduleCursor。

响应 data：完整 EmailConfig，前端读取 scheduleEnabled、scheduleCursor、scheduleNextRun。


15. POST /email/schedule/cancel

16. GET /email/extract/item-status

时机：用户开启邮件手动或定时提取后，与 GET /email/extract/status 一起轮询。

响应：
{
  "taskId": "任务 ID",
  "running": true,
  "scheduled": true,
  "items": [
    {"itemId": "Outlook EntryID", "status": "queued", "error": ""}
  ]
}

单邮件 status 值：queued（等待处理）、processing（正在读取/转换）、success（本轮处理成功）、failed（处理失败）、cancelled（任务取消）。定时任务运行时，前端应将 status 为 queued 或 processing 的邮件置为不可选；status=failed 可重新选择重试。不要把 matchedRule 当作处理状态，它只表示规则命中。

时机：用户在定时配置弹窗点击“取消当前定时”时调用。

请求体：{}，也可以不发送请求体。

响应 data：完整 EmailConfig。

使用：取消后 scheduleEnabled=false；scheduleSince 和 scheduleCursor 保留。


六、前端需要处理的错误码

403：当前网页 Origin 不在 LocalToolkit 白名单中。
404：取消提取时没有正在运行的任务。
409：已有邮件提取任务运行中，或运行期间尝试修改定时任务。
422：请求字段、时间范围、Cron、Skill 配置错误，或设置定时时没有有效提取规则。
426：当前 LocalToolkit 版本已停止服务，必须升级。
502：读取 Outlook 数据或下游服务调用失败。
503：Outlook 未安装、未登录或本机 Outlook 访问组件不可用。
500：LocalToolkit 内部错误。


七、页面主要调用顺序

初始化：
GET /health
→ GET /capabilities
→ /health 成功后立即渲染邮件主页，不显示 Outlook 状态灯
→ 并行调用 GET /email/skill/list、GET /email/config、GET /email/extract/status
→ 根据 GET /email/config 立即判断并显示/隐藏“无有效规则”红色提醒条
→ GET /email/folder/list，先渲染完整文件夹树并勾选 isDefault=true 的节点
→ POST /email/message/scan（folders 取当前勾选项）
→ 每 1 秒 GET /email/message/scan/status，表格区域显示“已读取 N 封”进度
→ status=done 后使用返回 items 展示本次扫描快照
→ 翻页只在本地快照上切片，不重新调用 Outlook

禁止：
- 增加 Outlook 安装状态、账号状态或状态灯；邮件主页只认 LocalToolkit /health。
- 等待 Outlook 状态检测后才显示邮件主页。
- 用全屏加载遮罩同时阻塞规则配置、时间范围和其他页面操作。

刷新邮件：
PUT /email/config（保存当前文件夹和规则）
→ 用户点击“刷新邮件”后 POST /email/message/scan（再次打开时 forceFull=false，优先增量读取）
→ 轮询 GET /email/message/scan/status
→ 扫描完成后 POST /email/message/list（只操作本地缓存）

手动提取：
PUT /email/config（保存弹窗配置）
→ POST /email/extract
→ 每 2 秒 GET /email/extract/status

定时增量：
PUT /email/config（先保存文件夹、有效规则和弹窗配置）
→ POST /email/schedule/set
→ 使用 GET /email/config 刷新定时状态

本次修改：新增 GET /email/extract/item-status，前端据此展示并禁用正在定时处理的单封邮件。
